# 같은 계정의 PC·스마트폰 동기화

메인 앱은 같은 출처의 `/api/v2`를 사용합니다. 로그인 세션은 기기마다 별도 발급되지만, 같은 이메일 계정은 같은 서버 워크스페이스를 읽습니다. 로컬 서버에서는 SQLite, Netlify에서는 강한 읽기와 조건부 쓰기를 사용하는 `next-xi-growth-v2` Blobs가 저장 기준입니다. 서로 다른 Netlify 프로젝트는 이 저장소를 자동 공유하지 않습니다.

화면이 보이고 입력·업로드 중이 아닐 때 5초 간격으로 선수 정보·실천·계획·영상·분석·이전 기록 목록을 갱신합니다. 탭 복귀·창 포커스·네트워크 복구 때도 갱신합니다. 입력 중인 폼과 재생 중인 모달은 보존하며 창을 닫거나 입력을 저장한 뒤 최신 기록을 받습니다. 날짜별 계획은 서버에 저장한 선수 설정·관찰·일정·실천 기록에서 계산합니다. 닫힌 앱으로 웹 푸시를 보내는 기능은 아닙니다.

저장은 화면에 표시됐던 값과 사용자가 바꾼 값, 서버 최신 값을 비교합니다. 서로 다른 필드는 병합하고 같은 필드의 서로 다른 변경은 거절합니다. 배열(실천 목록 등)의 동시 편집도 충돌로 알립니다. 입력은 폼에 유지되므로 별도 보관 후 창을 닫고 최신 기록을 확인해 다시 입력합니다. 서버 revision 검증은 그대로 적용하며 저장 중 발생한 revision 충돌은 같은 변경 의도로 한 번 재시도합니다. 저장 성공과 연결 상태는 하단에 표시합니다. 오프라인 자동 저장을 약속하지 않으며 실패한 폼은 유지됩니다.

## 직접 가져온 채팅 피드백

`/feedback.html`의 기존 JSON 가져오기는 계속 이 브라우저의 IndexedDB에만 저장합니다. 기존 자료는 자동 업로드하거나 삭제하지 않습니다. 홈에서 로그인한 뒤 피드백을 열고 **선택한 피드백을 계정에 저장**을 눌러야 서버로 전송됩니다. 계정 목록은 5초 간격으로 갱신하며 같은 계정의 다른 기기에서 열 수 있습니다. 계정 목록에서 연 피드백은 IndexedDB에 자동 복사하지 않습니다. 따로 기기에 저장한 사본은 로그아웃해도 남으므로 공용 기기에서는 직접 삭제해야 합니다.

계정당 최대 50개·합계 4MiB, 개별 JSON 1MiB입니다. 기존 ID와 내용이 같으면 중복 저장하지 않으며, 같은 ID의 다른 내용은 덮어쓰지 않습니다. 계정 목록의 삭제는 서버 사본만 삭제합니다. 계정 탈퇴 시 서버 피드백 내용을 제거하고 내용 없는 삭제 표식으로 진행 중인 저장의 복원을 막습니다. 채팅 피드백은 자동 분석 결과로 합치지 않습니다. 피드백 페이지에서 연결한 로컬 원본 영상도 자동 업로드하지 않습니다. 기기 간 원본 공유는 메인 앱의 비공개 영상 업로드를 사용합니다.

## 요청한 사이트에 배포하기

대상 주소는 `https://earnest-shortbread-008d93.netlify.app/`입니다. 과거 문서의 `courageous-entremet-c8f097`와 다른 프로젝트이므로 기존 검증 기록으로 이 주소의 연결 상태를 단정하지 않습니다.

Netlify에서 **대상 주소의 프로젝트**가 `jungin721-lang/Soccer`의 `next-xi-download-20261016` 브랜치에 연결됐는지 확인합니다. Node 24, `npm ci`, `npm run export`, 공개 폴더 `.artifacts/site`, 함수 폴더 `netlify/functions`를 사용합니다. 저장소의 `netlify.toml`이 이미 이 빌드 구성을 선언합니다. 정적 ZIP만 배포하면 로그인·서버 동기화가 제공되지 않습니다. Netlify의 런타임 Blobs 바인딩을 사용하며 계정 동기화를 위해 별도 AI 키가 필요하지 않습니다.

실제 배포 후 `/`의 `next-xi-version`이 `2.4.0-account-sync`인지, `/api/v2/status`가 HTML 대체 응답이 아닌 JSON인지 확인합니다. 키가 없을 때 `missing_credentials`는 AI 분석 상태이며 계정 저장 실패를 뜻하지 않습니다. 실제 계정·저장·두 세션·접근 격리 확인은 아래 검증 흐름으로 별도 수행합니다. 기존 브라우저를 계속 열어 둔 사용자는 배포 후 새로고침해야 새 코드를 사용합니다. HTML·JS는 기존 설정에 따라 재검증하며 API는 캐시하지 않습니다.

이번 환경에서 두 대상 호스트(사이트 및 `api.netlify.com`)는 프록시 CONNECT HTTP 403으로 차단됐고 Netlify 인증 변수와 로컬 프로젝트 연결 파일도 없었습니다. 따라서 실제 프로젝트 연결·Blobs 바인딩·배포 성공은 미확인입니다. 네트워크 허용 두 도메인은 환경 초안에 저장했지만 런타임 적용이나 Netlify 게시를 뜻하지 않습니다. 토큰을 채팅에 입력하지 말고 안전한 플랫폼 연결을 사용합니다.

동기화 검증은 임시 SQLite와 독립된 1440px PC·390px 모바일·320px 다른 계정 세션을 사용합니다. 실제 계정 로그인, 자동 갱신, 오래된 폼의 병합·충돌 보존, 실천 기록, 합성 H.264 원본의 다른 세션 접근·다른 계정 거절, 피드백 명시적 업로드·자동 목록 반영·세션 만료·재로그인과 새로고침을 확인합니다. 기존 성장 앱 검증은 업로드 재시도·원본 재생·이전 자료 가져오기도 검증합니다. 합성 데이터와 로컬 서버 결과이며 실제 휴대폰·Netlify 배포·AI 식별 정확도 검증을 대신하지 않습니다.
