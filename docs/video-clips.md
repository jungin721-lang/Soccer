# 스마트폰에서 작은 연속 영상 만들기 — v2.3

`/video-clips.html`은 스마트폰 원본을 짧은 **동영상 파일**로 다시 기록하는 무료 준비 도구입니다. 로그인, 서버 업로드, API 키와 유료 AI 호출을 사용하지 않습니다. 정지화면 자료는 기존 `/chat-pack.html`에서 계속 만들 수 있습니다.

## 사용 흐름

1. 사진 보관함 또는 파일 앱에서 원본을 한 번 선택합니다.
2. 유니폼 색·등번호·나이와 필요한 공유 권한을 확인합니다.
3. 첫 번째 영상 만들기를 누르고 화면을 켜 둡니다.
4. 만들어진 영상과 시간 정보 파일을 저장합니다. 영상 첨부가 지원되지 않으면 ‘채팅용 ZIP 만들기’로 영상·manifest.json·README.txt를 함께 묶어 저장합니다. ZIP은 최대 25MiB입니다. 지원 기기에서는 공유 버튼으로 직접 파일을 선택해 보낼 수 있습니다.
5. 다음 영상 만들기를 눌러 다음 구간을 준비합니다. 스마트폰 메모리를 위해 현재 결과 한 개만 유지하며, 저장 여부를 확인한 뒤 이전 결과를 정리합니다.
6. 사용자가 직접 영상과 설명을 채팅에 첨부합니다. 파일 준비와 채팅에서의 검토는 구분하며 분석이 완료됐다고 표시하지 않습니다.

## 시간과 크기

- 기본 구간은 원본의 1분 경계를 기준으로 합니다. 예: `00:00–01:00`, `00:55–02:00`, `01:55–03:00`. 두 번째부터 앞쪽 5초를 겹쳐 경계에서의 움직임을 보존합니다.
- 8분 21.801초 원본이면 9개 구간입니다. 파일을 무조건 7개로 고정하지 않습니다.
- 느린 기기나 큰 결과를 위한 30초 모드를 제공합니다. 사용자가 플레이 시각을 직접 지정할 필요는 없습니다.
- 한 결과는 24MiB 이하여야 합니다. 초과·녹화 중단·재생 실패를 성공으로 처리하지 않습니다. 실제 크기는 기기 인코더·영상 움직임에 따라 달라집니다.
- 최대 긴 변 1920px까지 종횡비를 유지합니다. 더 큰 원본은 축소됩니다. 음성은 포함하지 않습니다. 지원되는 브라우저에 따라 실제 MP4 또는 WebM으로 저장하고 확장자만 바꾸지 않습니다.
- 작은 등번호는 압축 전부터 읽기 어려울 수 있습니다. 결과를 확대해 확인할 수 있지만, 등번호 가독성과 선수 식별 정확도를 보장하지 않습니다.

## 처리와 개인정보

브라우저의 영상 디코더·Canvas·MediaRecorder를 사용합니다. 원본 전체를 JavaScript의 ArrayBuffer로 읽거나 외부로 전송하지 않습니다. 서버에서 MP4를 자르는 작업이나 바이트 배열의 단순 분할과 다릅니다. 대체로 영상 구간의 재생 시간만큼 기다려야 하며 화면 잠금·다른 앱 전환 시 중단될 수 있습니다. 취소하거나 중단된 구간은 원본을 다시 고르지 않고 같은 페이지에서 다시 시도할 수 있습니다. 새로고침·페이지 종료 후에는 원본 재선택이 필요합니다.

출력에는 장면 속 얼굴과 다른 선수도 포함됩니다. 공유는 사용자가 선택하며 공개 갤러리에 게시하지 않습니다. 시간 정보에는 대상 유니폼·번호·나이, 원본 길이·해상도, 요청·실제 시각 범위, 변환 방법과 분석 미수행 상태를 담습니다. 원본 파일명·선수 이름·계정·건강·생활 기록은 넣지 않습니다.

이 도구에는 **등번호 인식, 선수 추적, 자동 피드백 생성, 전체 경기의 모든 플레이 검증이 없습니다.** 채팅에 작은 영상을 첨부한 경우에도 사용 가능한 분석 도구와 첨부·사용 한도에 따라 확인 범위가 달라집니다. 이 환경에서는 첨부 영상에서 시간순 이미지를 추출해 확인할 수 있으며, 이것을 영상 전체의 연속 시청이나 추적 완료라고 표현하지 않습니다.

## 검증

```sh
npm run check
npm test
npm run test:video-clips
npm run test:feedback
npm run export
```

브라우저 검증에는 Python Playwright·Pillow, FFmpeg·FFprobe, `/usr/bin/chromium`이 필요합니다. 로컬 임시 HTTP 서버를 열 수 있는 실행 권한이 필요합니다. API·제3자 전송 없이 합성 원본으로 동영상 생성·디코딩·시간 범위·취소·모바일 레이아웃을 검사합니다. 실제 iPhone·Android·HEVC·8GiB 입력 전체·실제 선수 식별의 검증과 구분합니다.

## 배포

기존 Netlify 앱은 저장소 소스 전체를 배포해야 계정·원본 저장·분석 서버가 함께 유지됩니다. 새 페이지는 기존 `npm run export` 대상에 자동 포함됩니다. 정적 도구만 별도 사이트에 배포할 때에는 영상 준비 기능만 사용할 수 있습니다. 로컬 구현과 검증, GitHub 반영, Netlify Published 확인은 서로 다른 완료 상태입니다.
